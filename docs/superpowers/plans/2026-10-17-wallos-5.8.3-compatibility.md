# Wallos 5.8.3 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a locally verified Wallos Dial 1.0.0-rc.1 candidate based on patched Wallos 5.8.3, with safe browser cache updates and tested upgrade/rollback behavior.

**Architecture:** Keep Dial as a Docker source overlay pinned to a multi-architecture upstream digest. Merge the one upstream-changed overridden endpoint, verify the other security fixes inherited from the base, and override the 5.8.3 service worker so its static cache follows both Wallos and Dial versions. Use isolated synthetic data for HTTP, browser, upgrade, and rollback checks.

**Tech Stack:** Docker/Compose, PHP 8.3, SQLite3, Bash, Python 3, Service Worker.

**Spec:** docs/superpowers/specs/2026-10-17-wallos-dial-1.0-design.md

## Global Constraints

- Final release target: Dial 1.0.0; this compatibility milestone is 1.0.0-rc.1 in VERSION, the Docker label, local Compose tags, and DIAL_VERSION. Do not push a tag or image.
- Tested upstream: Wallos 5.8.3, pinned to bellamy/wallos:5.8.3@sha256:0006879778f31a962a3873f7682514b92a3c7665dcbc4764fcc241ad968eaccd. Docker Hub reported amd64 and arm64 children on 2026-10-17.
- Keep the pre-copy exact-file hash gate for every overridden upstream file. Hashes describe the unmodified base, never the Dial overlay.
- Preserve the five 0.1.1 email templates and plain-text alternatives. Incorporate all eleven upstream household owner predicates in the renewal notification override.
- The built image must contain the 5.8.2 server-side SSO-only direct POST guard and subscription foreign-key ownership checks.
- Never use private Wallos, public Demo, or any non-synthetic database or Logo mount for these tests. Keep the sample Compose port bound to loopback.
- The icon plan's authenticated endpoint is /endpoints/dial/icon.php?id=<int>. Every GET for that pathname is network-only in the service worker.
- The category manager and icon system plans follow this plan. They depend on its Wallos 5.8.3 base and the PHP constant DIAL_VERSION; the icon plan extends the static asset list with reviewed catalog icons.
- Push to GitHub, GHCR publication, Release, public Demo update, and the private Wallos deployment are separate later decisions.

## Review Focus

1. SSO-only instance + valid password sent directly to login.php: deny login and issue no authenticated session (Task 3 behavioral HTTP test).
2. An authenticated user submits another user's category, currency, household member, or payment method ID: fail without writing a subscription (Task 3 behavioral HTTP test).
3. A notification channel encounters another user's household ID: no foreign household row is resolved (Task 1 checks all eleven binding sites; Task 3 tests the predicate on two accounts).
4. A 0.1.1-controlled browser updates to the candidate and later a same-Wallos Dial build: fresh CSS/JS and a new static cache are used (Task 2 source test; Task 4 real browser test).
5. A populated 0.1.1 installation is upgraded, rolled back, written to with the old image, and upgraded again: original data, Logos, and SQLite integrity survive (Task 4).
